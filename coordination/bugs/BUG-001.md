# BUG-001 — Bloqueo de Scroll Vertical en Viewport por Confinamiento Root

- **Identificador:** BUG-001
- **Fecha:** 2 de noviembre de 2026
- **Estado:** RESUELTO POR EJECUTOR / PENDIENTE DE REVISIÓN INDEPENDIENTE CODEX
- **Severidad:** ALTA (Navegación crítica y acceso a productos bloqueado)
- **Componentes:** `css/style.css`, `tests/test-adversarial-r1.cjs`
- **Entorno de Verificación del Ejecutor:** Chromium / Brave (Playwright headless) con viewports emulados (Desktop 1366x768, Tablet Portrait 768x1024, Tablet Landscape 1024x768, Mobile 390x844).
  *Nota metodológica:* No se atribuyen resultados a WebKit/Safari, hardware físico de iPad ni trackpads reales, ya que no fueron ejecutados en este entorno.

---

## 1. Síntoma Reportado
El usuario no puede realizar desplazamiento vertical (scroll) en el catálogo, carrito ni vistas del sistema utilizando la rueda del ratón (mouse wheel) o desplazamiento en navegadores de escritorio y tablets emuladas. El contenido inferior queda inaccesible a pesar de que el documento excede largamente la altura de la pantalla (más de 3800 px).

---

## 2. Causa Raíz Técnica
1. **Promoción forzada de `overflow-y` según especificación CSS Overflow:**
   La regla original en `css/style.css`:
   ```css
   html, body {
     max-width: 100vw;
     overflow-x: hidden;
     position: relative;
   }
   ```
   De acuerdo con el estándar W3C CSS Overflow Module Level 3, si `overflow-x` tiene un valor distinto de `visible` (como `hidden`), los navegadores promueven automáticamente `overflow-y: visible` a `overflow-y: auto`.
2. **Doble contenedor de scroll anidado:**
   Al aplicar esta regla simultáneamente a `html` y `body`, ambos elementos se convierten en contenedores de scroll independientes. Esto confunde el enrutamiento de eventos nativos en navegadores Blink: los eventos de rueda (`wheel`) dirigidos al documento no mueven `window.scrollY`.
3. **Comportamiento de `overscroll-behavior`:**
   La propiedad `overscroll-behavior-y: none;` en `body` elimina el rebote elástico y evita el encadenamiento hacia el scroll superior en bordes; aunque no cancela los eventos por sí misma, su remoción en el body previene rigidez en los límites de interacción.
4. **Dependencia circular de tests heredados:**
   Una prueba adversarial de strings en `tests/test-adversarial-r1.cjs` exigía explícitamente el patrón regex `/html\s*,\s*body\s*\{[\s\S]*?overflow-x:\s*hidden;/i`, forzando artificialmente la permanencia de la regla defectuosa.

## 4. Solución Implementada

1. **Reemplazo de `hidden` por `clip` y liberación de `body` en `css/style.css`:**
   ```css
   /* Guardia global contra desbordamiento horizontal en pantallas móviles (360px - 430px) y restauración de scroll vertical nativo (QA-A / BUG-001) */
   html {
     max-width: 100vw;
     overflow-x: clip;
     overflow-y: auto;
     position: relative;
   }

   body {
     max-width: 100vw;
     overflow-x: clip;
     overflow-y: visible;
     position: relative;
     font-family: 'Plus Jakarta Sans', -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif;
     -webkit-tap-highlight-color: transparent;
     background-color: var(--bg-canvas, #f8fafc);
     color: var(--text-primary, #0f172a);
     -webkit-font-smoothing: antialiased;
     transition: background-color 0.2s ease, color 0.2s ease;
     min-height: 100vh;
     min-height: 100dvh;
     padding-bottom: env(safe-area-inset-bottom, 0px);
   }
   ```
   - `overflow-x: clip`: Corta cualquier elemento que exceda el ancho del viewport sin crear un contenedor de scroll artificial ni promover `overflow-y` a `auto`.
   - `html { overflow-y: auto; }`: Permite que la ventana del navegador gestione de forma natural el desplazamiento vertical.
   - `body { overflow-y: visible; }`: Garantiza que el cuerpo del documento delegue libremente el scroll al viewport.
   - Se removió `overscroll-behavior-y: none` del cuerpo.
   - Se conservaron intactas las categorías con scroll horizontal (`.no-scrollbar` con `overflow-x: auto`), sin imponer `touch-action: pan-y`.

2. **Actualización Justificada de Aserción en `tests/test-adversarial-r1.cjs`:**
   Se flexibilizó la aserción de guarda de desbordamiento para aceptar tanto `overflow-x: clip` como `overflow-x: hidden`:
   ```javascript
   const hasRootOverflowGuard = /(?:html|body)[\s\S]*?max-width:\s*100vw;[\s\S]*?overflow-x:\s*(?:clip|hidden);/i.test(cssContent);
   ```
